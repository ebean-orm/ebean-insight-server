# Development demo data

The repeatable UX data set is generated by
`server/src/test/java/main/SeedDemoData.java`.

## What it provides

The seed creates or refreshes a representative `shop-app` application and
`prod` environment with:

- The datasource-pool dashboard enabled in the application's JSONB
  application configuration.
- 1-minute, 10-minute, and 1-hour rollup history.
- Multiple labels and query hashes.
- Query-family timing values.
- Query-plan rows, including plan-shape changes.
- Long production-style locations for wrapping and table-layout testing.
- Stored SQL and metric metadata used by `/ux/query-hash`.

The seed uses a fixed random seed so generated values are repeatable enough for
local UI work.

## Running the seed

Start PostgreSQL and configure the same database properties used by the local
server, then run:

```shell
mvn -q -pl server \
  -Dexec.mainClass=main.SeedDemoData \
  -Dexec.classpathScope=test \
  org.codehaus.mojo:exec-maven-plugin:3.5.0:java
```

The tool extends partitions, removes the prior seeded rollup/plan rows, and
repopulates the time windows. Existing metric identity rows are also refreshed
with the seeded location and SQL metadata.

The output includes the seeded application, environment, row counts, and a
starting URL such as:

```text
http://localhost:8091/ux/top?app=shop-app&range=30m
```

## When to update seed data

Update the seed when a UI change needs deterministic coverage for a new
behavior, such as:

- empty or null chart buckets;
- long labels, hashes, SQL, or locations;
- multiple query hashes under one label;
- missing or changed query plans;
- timestamps and selected-window statistics.

Keep seeded data realistic and avoid coupling tests to incidental random
values. If a new scenario needs a different database state, prefer adding a
small focused test fixture rather than making the general seed increasingly
specialized.
